## Bugs Found

### BUG-001: Helper Script Session Number Detection
**Severity:** 🟡 Moderate
**Impact:** Incorrect session numbering, confusion

**What happened:**
- Helper script detected "Session 6" for first-ever session
- Counted template/example sessions as real sessions
- Grep pattern: `grep -c "^## Session" context/SESSIONS.md` counted:
  1. Template header (line 10)
  2. "## Example: Initial Session" (line 104)
  3. Example session entry (line 108)
  4. "## Session Template" (line 145)
  5. Template in code block (line 148)
- Total: 5 matches → Next session = 6 (WRONG)

**Expected behavior:**
- Should detect Session 1 (no real sessions exist)
- Should ignore templates, examples, and code blocks
- Should only count actual session entries

**Reproduction:**
1. Fresh install with template SESSIONS.md
2. Run `./scripts/save-context-helper.sh`
3. Observe: "Next session: 6"

**Fix suggestion:**
```bash
# Current (WRONG):
LAST_SESSION=$(grep -c "^## Session" context/SESSIONS.md)

# Proposed (BETTER):
# Count only sessions before "## Example:" or "## Session Template"
LAST_SESSION=$(sed -n '/^## Session [0-9]/p' context/SESSIONS.md | \
               grep -v "Template" | grep -v "Example" | wc -l | tr -d ' ')
```

**Workaround used:** Manually corrected session number from 6 to 1

## Friction Points

### FRICTION-001: Meta-Project Git Detection
**Severity:** 🟢 Minor (expected behavior, but messaging confusing)
**Impact:** Confusing message for meta-project users

**What happened:**
```
📊 Gathering git information...
   ⏭️  Not a git repository (skipping git data)
```

**Issue:**
- Technically correct (parent directory is not a git repo)
- But misleading for meta-projects (sub-repos ARE git repos)
- Message doesn't distinguish between:
  - "No git repo anywhere" (true non-git project)
  - "Meta-project with sub-repos" (our case)

**Suggestion:**
```bash
# Detect meta-project scenario
if [ -d .git ]; then
  echo "   ✅ Git repository detected"
elif find . -maxdepth 2 -name ".git" -type d | grep -q .; then
  echo "   ℹ️  Meta-project detected (sub-repos have git)"
else
  echo "   ⏭️  Not a git repository (skipping git data)"
fi
```

**Impact:** Low (doesn't break functionality, just confusing)

## Detailed Bug Reports for GitHub

### Issue: Helper Script Counts Template Sessions

**Title:** save-context-helper.sh incorrectly counts template sessions as real sessions

**Description:**
The session number detection in `save-context-helper.sh` counts ALL lines matching `^## Session` including:
- Template placeholders
- Example sessions
- Sessions in code blocks

This causes incorrect session numbers (e.g., "Session 6" for first real session).

**Expected:** Count only actual session entries (exclude templates/examples/code blocks)

**Proposed Fix:**
```bash
# Better detection that excludes templates
LAST_SESSION=$(sed -n '1,/^## Example/p' context/SESSIONS.md | \
               grep -c "^## Session [0-9]")
```

**Impact:** Moderate - Affects all first-time users

---

### Issue: Quick Reference Not Auto-Generated

**Title:** Quick Reference section requires manual population despite "auto-generated" label

**Description:**
STATUS.md includes note: "_(This section is auto-generated by /save and /save-full - DO NOT edit manually)_"

However, running /save-full does NOT auto-populate this section. All fields must be manually filled.

**Expected:** Extract values from:
- `.context-config.json` (project name, URLs, tech stack, commands)
- `STATUS.md` content (current phase, active tasks)
- `SESSIONS.md` (last session)

**Proposed Fix:** Implement the extraction logic shown in /save-full Step 5 (currently just documentation, not executed)

**Impact:** High - False advertising of feature, significant manual work required
