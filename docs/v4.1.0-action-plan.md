## Priority 1: Critical Bug Fixes

### P1.1: ANSI Escape Codes Not Rendering

**Source:** Both palisades-fire and ncl feedback

**Problem:** Raw escape codes display as literal text:
```
\033[0;32m✅ Fixed version sync\033[0m
```

**Cause:** Using `echo` without `-e` flag in installer

**Fix:** Change from `echo` to `printf` or `echo -e`

**Files to modify:**
- `install.sh` - Find all `echo` statements with `\033` and fix

**Test:** Run `/update-context-system` and verify colors render properly

---

### P1.2: update-quick-reference.sh Fails with Negative Line Count

**Source:** ncl feedback

**Problem:** Script fails on macOS with:
```
head: illegal line count -- -1
```

**Cause:** Empty variable or arithmetic returning negative number when calculating line positions

**Fix:** Add defensive validation:
```bash
# Before using head with calculated line count
if [ -z "$LINE_COUNT" ] || [ "$LINE_COUNT" -lt 1 ]; then
  echo "Warning: Could not calculate line count, skipping Quick Reference update"
  exit 0
fi

# Or use defensive arithmetic
LINE_COUNT=$((${LINE_NUM:-1} - 1))
[ "$LINE_COUNT" -lt 0 ] && LINE_COUNT=0
```

**Files to modify:**
- `scripts/update-quick-reference.sh`

**Test:** Run script with various STATUS.md formats, including empty/minimal files

---

### P1.3: /code-review Audit Discovery Fails from Subdirectory

**Source:** ncl feedback

**Problem:** `ls .claude/commands/code-review-*.md` fails when user is in monorepo subdirectory (e.g., `apps/web/`)

**Cause:** Uses relative path without finding git root

**Fix:** Use git root detection:
```bash
REPO_ROOT=$(git rev-parse --show-toplevel 2>/dev/null || pwd)
ls "$REPO_ROOT/.claude/commands/code-review-*.md" 2>/dev/null
```

Or use `find_context_folder` pattern already established in other commands.

**Files to modify:**
- `.claude/commands/code-review.md` - Update audit discovery step

**Test:** Run `/code-review` from both project root and subdirectory

## Priority 2: Minor Bug Fixes

### P2.1: Feedback Archive Uses Destination Version

**Source:** ncl feedback

**Problem:** Archive named `feedback-v4.0.1-...` but contains v3.6.0 feedback

**Cause:** `get_system_version()` called after installer updates VERSION file

**Fix:** Capture version before running installer:
```bash
# Before installer runs
OLD_VERSION=$(cat VERSION 2>/dev/null || echo "unknown")

# Later, during archiving
ARCHIVE_FILE="artifacts/feedback/feedback-v${OLD_VERSION}-${ARCHIVE_DATE}.md"
```

**Files to modify:**
- `.claude/commands/update-context-system.md` - Capture version early

**Test:** Upgrade and verify archive filename matches source version

---

### P2.2: Redundant Step 2.3 (Version Sync)

**Source:** palisades-fire feedback

**Problem:** Installer auto-fixes version sync, then command Step 2.3 does it again

**Fix:** Remove Step 2.3 or make it conditional:
```bash
# Only run if installer didn't already fix it
if [ "$(jq -r '.version' context/.context-config.json)" != "$(cat VERSION)" ]; then
  # Update version
fi
```

**Recommendation:** Remove Step 2.3 entirely - installer handles this now.

**Files to modify:**
- `.claude/commands/update-context-system.md` - Remove or conditionalize Step 2.3

---

### P2.3: Feedback Detection Includes Template Examples

**Source:** ncl feedback

**Problem:** Template examples between "Feedback Entries" and "Examples" markers may trigger archiving

**Fix:** Use more precise detection:
```bash
# Count only lines that look like real user entries (## YYYY-MM-DD format)
USER_ENTRIES=$(grep -c "^## [0-9]\{4\}-[0-9]\{2\}-[0-9]\{2\}" context/context-feedback.md 2>/dev/null || echo "0")
if [ "$USER_ENTRIES" -gt 0 ]; then
  # Has real user feedback - archive it
fi
```

**Files to modify:**
- `.claude/commands/update-context-system.md` - Update feedback detection logic

## Priority 4: CLAUDE.md Health Checking (New Feature)

### Overview

Add proactive health checks to `/review-context` and `/save-full` that:
1. Compare CLAUDE.md against CONTEXT.md
2. Detect potential drift (tech stack, URLs, staleness)
3. Make specific recommendations

### P4.1: Helper Function in common-functions.sh

**Function:** `check_claude_md_health()`

**Logic:**
1. Check if both CLAUDE.md and CONTEXT.md exist
2. Compare modification dates (threshold: 30 days)
3. Extract and compare tech stack keywords
4. Extract and compare URLs
5. Check for template placeholders (P3.3)
6. Generate recommendations

**Output format:**
```
CLAUDE_MD_STATUS="healthy|stale|drift|missing"
CLAUDE_MD_DAYS_OLD=N
CLAUDE_MD_RECOMMENDATIONS="..."
```

## Thresholds and Tuning

### Staleness
- **Green:** CLAUDE.md within 14 days of CONTEXT.md
- **Yellow:** 15-30 days older
- **Red:** 30+ days older

### Tech Stack Comparison
- Only flag technologies in CONTEXT.md missing from CLAUDE.md
- Require 2+ missing technologies to flag (avoid false positives)

### Template Placeholders
- Flag any `[FILL:` patterns found in CONTEXT.md
- Count and report number found
