| 8 | .claude/commands/code-review-performance.md | 164 | `"width\|height"` | Works | Optional: convert to ERE |

### Root Cause Analysis

The bug affects BRE patterns that combine:
- `^` anchor at start of pattern
- Alternation with `\|`
- Special characters like `==` or `--` after the anchor

**Broken pattern:** `grep -v '^#\|^$\|^==\|^--'`
- Works: `'^#\|^$'` (simpler patterns)
- Fails: Adding `\|^==` causes BSD grep to misbehave

**Working patterns:** Those without `^` anchors or with simpler combinations work fine.

### Test Evidence

```bash
# Test file: /tmp/test-readme.md
# Project Title
================

A test description line.

## Features

# BRE pattern (broken):
$ grep -v '^#\|^$\|^==\|^--' /tmp/test-readme.md | head -1
# Result: '' (empty - gets blank line)

# ERE pattern (fixed):
$ grep -vE '^#|^$|^==|^--' /tmp/test-readme.md | head -1
# Result: 'A test description line.'
```

### Decision

1. **MUST FIX:** scripts/common-functions.sh:2194 - Breaks functionality
2. **SHOULD FIX:** Convert all BRE alternation to ERE for consistency and future-proofing
3. **Rationale:** ERE (`-E`) is more portable and readable; no downside to using it

## Phase 0.3: BUG-C Debug Output Reproduction

### Test Command
```bash
zsh -c 'source scripts/common-functions.sh && output=$(generate_session_index "/tmp/test-sessions.md" 2>&1) && echo "$output" | grep -E "line_num=|context_lines="'
```

### Results: BUG CONFIRMED (zsh-specific)

**Output:**
```
line_num=13
context_lines=$'**Status:** ✅ Complete
```

### Root Cause

Lines 3938-3944 in `generate_session_index()` use the pattern:
```bash
local line_num
line_num=$(...)
local context_lines
context_lines=$(...)
```

In zsh, when `local var` is declared on one line and then assigned on the next inside a loop, zsh prints the assignment to stdout. This is the same issue that was fixed in commit `fc63968` for `is_security_relevant`.

### Fix Required

Combine declaration and assignment:
```bash
local line_num=$(...)
local context_lines=$(...)
```

### Note

This bug does NOT reproduce in bash, only in zsh. Since macOS default shell is zsh, this affects many users.

## Phase 0.4: BUG-B Parent Detection Reproduction

### Test Setup
```bash
mkdir -p /tmp/test-sibling/{project-a,project-b/.claude}
cd /tmp/test-sibling/project-a
```

### Test Command
```bash
find "$PWD/.." -maxdepth 2 -name ".claude" 2>/dev/null
```

### Results: BUG CONFIRMED

**Output:**
```
/tmp/test-sibling/project-a/../project-b/.claude
```

### Root Cause

The `find` command with `-maxdepth 2` from the parent directory (`$PWD/..`) searches all subdirectories at depth 1-2, which includes sibling directories.

**Current behavior:**
```
/tmp/test-sibling/           <- parent
├── project-a/               <- current directory (PWD)
└── project-b/               <- sibling
    └── .claude/             <- INCORRECTLY DETECTED
```

**Desired behavior:**
Only check direct ancestors of the current directory, not siblings:
```
/tmp/test-sibling/.claude    <- check this
/tmp/.claude                 <- check this
...
```

### Fix Required

Replace `find`-based detection with ancestor-walking function that only checks direct parent directories:

```bash
check_ancestor_claude() {
  local current="$1"
  local parent
  local levels=0
  local max_levels=3

  while [ $levels -lt $max_levels ]; do
    parent=$(dirname "$current")
    [ "$parent" = "$current" ] && return 1
    [ -d "$parent/.claude" ] && { echo "$parent/.claude"; return 0; }
    current="$parent"
    levels=$((levels + 1))
  done
  return 1
}
```
