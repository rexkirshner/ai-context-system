### Task 1.1: Fix grep -c arithmetic in organize-docs

**Problem:** In zsh, when `grep -c` finds no matches, the command substitution returns an empty string, causing arithmetic to fail:

```bash
# This fails in zsh when grep finds no matches
count=$(($(grep -c "pattern" file)))
# Error: zsh: bad math expression: empty string
```

**File:** `.claude/commands/organize-docs.md`

**Solution:** Use `|| echo 0` fallback and ensure variable is numeric:

```bash
# Before (broken in zsh)
FILE_COUNT=$(($(grep -c "\.md$" file)))

# After (works in all shells)
FILE_COUNT=$(grep -c "\.md$" file 2>/dev/null || echo "0")
FILE_COUNT=$((FILE_COUNT + 0))  # Ensure numeric
```

**Verification:**
```bash
# Test in zsh
zsh -c '
  echo "no matches here" > /tmp/test.txt
  count=$(grep -c "NOTFOUND" /tmp/test.txt 2>/dev/null || echo "0")
  count=$((count + 0))
  [ "$count" -eq 0 ] && echo "PASS" || echo "FAIL: got $count"
  rm /tmp/test.txt
'
```

**Checkpoint 1.1:**
- [ ] All `grep -c` in organize-docs use `|| echo "0"` fallback
- [ ] Arithmetic operations protected with `+ 0`
- [ ] Script runs without error in zsh
- [ ] Script runs without error in bash

### Task 1.2: Fix $MV_CMD variable expansion with safe move_file()

**Problem:** Variable assignment and expansion syntax can differ between shells when the variable contains spaces:

```bash
# This may fail in some shells
MV_CMD="git mv"
$MV_CMD source dest  # Word splitting issues
```

**Additional Problems (from QA Review):**
- No directory creation for destination
- No protection against overwriting existing files
- No error handling for failed moves

**File:** `.claude/commands/organize-docs.md`

**Solution:** Use a robust function with safety checks:

```bash
# Before (problematic)
if git rev-parse --git-dir > /dev/null 2>&1; then
  MV_CMD="git mv"
else
  MV_CMD="mv"
fi
$MV_CMD "$source" "$dest"

# After (robust with safety checks)
move_file() {
  local source="$1"
  local dest="$2"
  local force="${3:-false}"  # Optional: skip confirmation

  # Validate source exists
  if [ ! -e "$source" ]; then
    echo "Error: Source file does not exist: $source" >&2
    return 1
  fi

  # Create destination directory if needed
  local dest_dir
  dest_dir=$(dirname "$dest")
  if [ ! -d "$dest_dir" ]; then
    mkdir -p "$dest_dir" || {
      echo "Error: Cannot create directory: $dest_dir" >&2
      return 1
    }
  fi

  # Check for destination conflict
  if [ -e "$dest" ] && [ "$force" != "true" ]; then
    echo "Warning: Destination exists: $dest" >&2
    echo "  Use force=true to overwrite, or resolve manually" >&2
    return 1
  fi

  # Perform the move
  if git rev-parse --git-dir > /dev/null 2>&1 && git ls-files --error-unmatch "$source" > /dev/null 2>&1; then
    # File is tracked by git, use git mv
    if [ "$force" = "true" ] && [ -e "$dest" ]; then
      git mv -f "$source" "$dest"
    else
      git mv "$source" "$dest"
    fi
  else
    # Not in git or file not tracked, use regular mv
    mv "$source" "$dest"
  fi
}

# Usage
move_file "$source" "$dest"
# Or with force: move_file "$source" "$dest" "true"
```

**Verification:**
```bash

  echo "Testing in $shell..."
  $shell -c '
    mkdir -p /tmp/mv-test
    echo "content" > /tmp/mv-test/file.txt

      fi

      dest_dir=$(dirname "$dest")
      if [ ! -d "$dest_dir" ]; then
        mkdir -p "$dest_dir" || return 1
      fi

      if [ -e "$dest" ] && [ "$force" != "true" ]; then

      fi

      mv "$source" "$dest"
    }

    # Test 1: Basic move
    move_file /tmp/mv-test/file.txt /tmp/mv-test/moved.txt
    [ -f /tmp/mv-test/moved.txt ] && echo "  ✓ Basic move" || echo "  ✗ Basic move"

    # Test 2: Create destination directory
```

### Task 2.3: Create code block aware parser (with safe delimiter)

**File:** `scripts/export-sessions-json.sh`

**Problem:** Content inside markdown code blocks (```) is parsed as if it were real content.

**Critical Fix (from QA Review):** The original design used `:` as delimiter in `SESSION_START:number:date:title`. This BREAKS when titles contain colons, e.g., "Feature: Authentication" would be parsed as just "Feature".

**Solution:** Use `|||` as delimiter instead (extremely unlikely to appear in titles):

```bash
# Parse SESSIONS.md while respecting code blocks
#
# Usage:
#   parse_sessions "context/SESSIONS.md" | process_each_line
#
# Output format (one per line):
#   SESSION_START|||number|||date|||title
#   SESSION_CONTENT|||line
#   SESSION_END
#
# NOTE: Uses ||| as delimiter because:
# - Colons (:) appear in titles like "Feature: Auth"
# - Pipes (|) appear in markdown tables
# - Triple-pipe is extremely unlikely in natural text
#
FIELD_DELIMITER="|||"

parse_sessions_file() {
  local file="$1"
  local in_code_block=false
  local in_session=false
  local current_session=""

  # Stop before template/example sections
  local content
  content=$(sed -n '1,/^## \(Example\|Session Template\)/p' "$file" 2>/dev/null)

  while IFS= read -r line; do
    # Track code block state
    if [[ "$line" =~ ^\`\`\` ]]; then
      if [ "$in_code_block" = "true" ]; then
        in_code_block=false
      else
        in_code_block=true
      fi
      continue
    fi

    # Skip content inside code blocks
    if [ "$in_code_block" = "true" ]; then
      continue
    fi

    # Check for session header
    if [[ "$line" =~ ^##\ Session\ ([0-9]+) ]]; then
      # Close previous session if open
      if [ "$in_session" = "true" ]; then
        echo "SESSION_END"
      fi

      # Parse session header
      local session_num="${BASH_REMATCH[1]}"
      local date=""
      local title=""

      # Try pipe format: ## Session N | DATE | TITLE
      if [[ "$line" =~ \|\ ([0-9]{4}-[0-9]{2}(-[0-9]{2})?)\ \|\ (.+)$ ]]; then
        date="${BASH_REMATCH[1]}"
        title="${BASH_REMATCH[3]}"
      # Try pipe format without title: ## Session N | DATE
      elif [[ "$line" =~ \|\ ([0-9]{4}-[0-9]{2}(-[0-9]{2})?)$ ]]; then
        date="${BASH_REMATCH[1]}"
        title=""
      # Try dash format: ## Session N - DATE
      elif [[ "$line" =~ -\ ([0-9]{4}-[0-9]{2}(-[0-9]{2})?) ]]; then
        date="${BASH_REMATCH[1]}"
        title=""
      fi

      echo "SESSION_START${FIELD_DELIMITER}${session_num}${FIELD_DELIMITER}${date}${FIELD_DELIMITER}${title}"
      in_session=true
      continue
    fi

    # Regular content line
    if [ "$in_session" = "true" ]; then
      echo "SESSION_CONTENT${FIELD_DELIMITER}${line}"
    fi

  done <<< "$content"

  # Close final session
  if [ "$in_session" = "true" ]; then
    echo "SESSION_END"
  fi
}
```

**Verification:**

```bash
json_escape() {
  local str="$1"
  # Escape backslashes first, then quotes, then control characters
  str="${str//\\/\\\\}"
  str="${str//\"/\\\"}"
  str="${str//$'\n'/\\n}"
  str="${str//$'\t'/\\t}"
  str="${str//$'\r'/\\r}"
  echo "$str"
}

# Generate JSON object for a session
#
# Usage:
#   generate_session_json 1 "2026-01-01" "Title" "TL;DR content" "Complete"
#
generate_session_json() {
  local num="$1"
  local date="$2"
  local title="$3"
  local tldr="$4"
  local status="$5"

  cat << EOF
{
  "sessionNumber": $num,
  "date": "$(json_escape "$date")",
  "title": "$(json_escape "$title")",
  "tldr": "$(json_escape "$tldr")",
  "status": "$(json_escape "$status")"
}
EOF
}
```

```bash
    mv "$temp_file" "$output_file"
```

### Task 3.1: Fix Current Focus extraction pattern

**Problem:** Script looks for `**In Progress:**` but real STATUS.md files use different formats like `## Active Tasks` or `**Next Priorities:**`.

**File:** `scripts/update-quick-reference.sh`

**Current (too specific):**
```bash

```

**New (flexible cascade):**
```bash
# Extract current focus using multiple pattern fallbacks
#
# Tries in order:
# 1. **In Progress:** section with - [ ] items
# 2. **Next Priorities:** under ## Active Tasks
# 3. First unchecked - [ ] anywhere
# 4. ## Current Focus header content
#
extract_current_focus() {
  local file="$1"
  local focus=""

  # Try 1: **In Progress:** with unchecked items
  focus=$(grep -A 5 "\*\*In Progress:\*\*" "$file" 2>/dev/null | \
          grep "^\- \[ \]" | head -1 | sed 's/^- \[ \] //')
  if [ -n "$focus" ]; then
    echo "$focus"
    return 0
  fi

  # Try 2: **Next Priorities:** under Active Tasks
  focus=$(sed -n '/## Active Tasks/,/^## /p' "$file" 2>/dev/null | \
          grep -A 5 "\*\*Next Priorities:\*\*" | \
          grep "^\- " | head -1 | sed 's/^- //')
  if [ -n "$focus" ]; then
    echo "$focus"
    return 0
  fi

  # Try 3: First unchecked item anywhere
  focus=$(grep "^\- \[ \]" "$file" 2>/dev/null | head -1 | sed 's/^- \[ \] //')
  if [ -n "$focus" ]; then
    echo "$focus"
    return 0
  fi

  # Try 4: ## Current Focus section
  focus=$(sed -n '/^## Current Focus/,/^## /p' "$file" 2>/dev/null | \
          grep -v "^## " | grep -v "^$" | head -1)
  if [ -n "$focus" ]; then
    echo "$focus"
    return 0
  fi

  # Fallback
  echo "See STATUS.md"
}
```

### Task 5.1: Add TTY detection for color output (improved regex)

**Problem:** ANSI color codes appear in piped output.

**QA Review Note:** The original regex `\x1b\[[0-9;]*m` only matches color codes. ANSI escapes include cursor movement, clearing, etc. Use a more comprehensive pattern.

**File:** `scripts/common-functions.sh`

**Add TTY detection to color_echo:**
```bash
# Color output only if stdout is a terminal
#
# Usage:
#   color_echo "${RED}Error${NC}"
#   color_echo "${GREEN}Success${NC}"
#
# Handles all ANSI escape sequences:
# - Colors: \e[31m (red), \e[0m (reset), etc.
# - Cursor: \e[2J (clear), \e[H (home), etc.
# - Extended: \e[38;5;XXXm (256 colors), \e[38;2;R;G;Bm (24-bit)
#
color_echo() {
  if [ -t 1 ]; then
    # stdout is a terminal, use colors
    echo -e "$1"
  else
    # stdout is piped/redirected, strip ALL ANSI escape sequences
    # Pattern explanation:
    #   \x1b or \033 - escape character
    #   \[           - CSI (Control Sequence Introducer)
    #   [0-9;?]*     - parameters (including ? for private sequences)
    #   [A-Za-z]     - final byte (command)
    echo -e "$1" | sed 's/\x1b\[[0-9;?]*[A-Za-z]//g'
  fi
}

# Alternative using perl (more portable across sed versions):
color_echo_portable() {
  if [ -t 1 ]; then
    echo -e "$1"
  else
    if command -v perl > /dev/null 2>&1; then
      echo -e "$1" | perl -pe 's/\e\[[0-9;?]*[A-Za-z]//g'
    else
      # Fallback - basic sed (may not work on all systems)
      echo -e "$1" | sed 's/\x1b\[[0-9;?]*[A-Za-z]//g'
    fi
  fi
}
```
