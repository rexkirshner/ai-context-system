## Task 8.1: Fix STATUS.template.md Duplicate Timestamp

### Problem
The STATUS.template.md has two "Last Updated" lines:
- Line 3: `**Last Updated:** [Auto-updated by /save]`
- Line 112: `**Last Updated:** [Auto-updated by /save-context]`

Issues:
1. Duplicate information creates confusion
2. Footer references obsolete command name (`save-context` → `save`)
3. Which one gets updated? (Answer: header only)

### Solution
Remove the footer timestamp entirely. The header timestamp is sufficient and is the one actually updated by scripts.

### Verification
```bash
# Should return exactly 1 line
grep -c "Last Updated" templates/STATUS.template.md
# Expected: 1

# Should reference correct command
grep "Last Updated" templates/STATUS.template.md | grep -q "save]"
# Expected: exit 0 (success)
```

### Files Changed
- `templates/STATUS.template.md`

## Task 8.2: Add KNOWN_ISSUES.md Staleness Check

### Problem
KNOWN_ISSUES.md often becomes stale:
- Issues get fixed but entries remain
- AI agents don't proactively check this file
- No validation catches this drift

### Solution
Add KNOWN_ISSUES.md to the /review-context verification checklist.

The check should:
1. Verify file exists (if project uses it)
2. Flag if file hasn't been updated in >30 days
3. Suggest reviewing for resolved issues

### Implementation Location
Add to `.claude/commands/review-context.md` in the verification section (Step 4 or 5).

### Verification
```bash

grep -q "KNOWN_ISSUES" .claude/commands/review-context.md
# Expected: exit 0 (success)
```

### Files Changed

## Task 8.3: Document Canonical Session Header Format

### Problem
Two session header formats exist in the wild:
1. Pipe format: `## Session N | YYYY-MM-DD | Phase Name` (canonical)
2. Dash format: `## Session N - YYYY-MM-DD` (legacy)

The code handles both (see `get_next_session_number()`), but:
- No documentation states which is preferred
- New users might use inconsistent formats
- Pattern matching could be confused

### Solution
1. Add explicit note in SESSIONS.template.md about canonical format
2. Ensure all examples use pipe format consistently
3. Add migration note for dash format users

### Verification
```bash
# Template should document the canonical format
grep -q "pipe format\|canonical\|preferred format" templates/SESSIONS.template.md
# Expected: exit 0 (success)

# All session examples should use pipe format
grep "## Session [0-9]" templates/SESSIONS.template.md | grep -v "|"
# Expected: no output (all use pipe format)
```

### Files Changed
- `templates/SESSIONS.template.md`
