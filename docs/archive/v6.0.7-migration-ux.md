# v6.0.7 Planning: Migration UX Issue

**Date:** 2026-01-27
**Status:** Open - needs decision

## Current State

The pre-v6 migration flow currently requires users to:

1. Run `migrate-to-v6.sh`
2. Restart Claude Code
3. Run `/init-context` (which detects migration state and handles it)
4. Verify with `/save`

## The Problem

**Confusing naming:** Users migrating from v5.x are expected to run `/init-context`, which sounds like it's for initializing NEW projects, not migrating existing ones.

The command does the right thing (detects old files, migrates them), but the name doesn't match the action from the user's perspective.

## Options

### Option 1: Create `/migrate-context`

Create a dedicated command for completing pre-v6 migrations.

**Pros:**
- Clear naming: "I'm migrating, I run migrate"
- `/init-context` stays focused on fresh projects
- Easy to document

**Cons:**
- Another command to maintain
- User has to know which command to run (though migrate-to-v6.sh would tell them)

**Implementation:**
- Create `.claude/commands/migrate-context.md` with migration logic
- Update `migrate-to-v6.sh` to say "Run `/migrate-context`"
- Keep `/init-context` for fresh projects only

### Option 2: Rename to `/setup-context`

One command that handles both initialization and migration.

**Pros:**
- Single command for all "get context working" scenarios
- "Setup" is more neutral than "init"

**Cons:**
- Still not obvious to migrators
- Breaking change for existing users who know `/init-context`
- "Setup" is vague

**Implementation:**
- Rename `init-context.md` to `setup-context.md`
- Update all docs
- Keep dual-mode behavior

### Option 3: Have `migrate-to-v6.sh` do everything

The bash script handles context file migration too, no second command needed.

**Pros:**
- Simplest user experience: run script, restart, done
- No confusion about which command to run
- Migration is truly complete when script finishes

**Cons:**
- Bash script doing context file transformation is less intelligent than Claude
- Script would need to parse and transform markdown files
- Can't extract nuanced context the way Claude can
- More complex bash script

**Implementation:**
- Enhance `migrate-to-v6.sh` to:
  - Read old context files
  - Generate v6.0 format files (simple transformation)
  - Delete old files
  - Add Session Loop to CLAUDE.md
- Remove migration mode from `/init-context`

## Recommendation

**Option 1 (Create `/migrate-context`)** seems like the best balance:
- Clear UX for both fresh installs and migrations
- Claude handles the intelligent context extraction
- Simple implementation

But this decision was deferred for a big-picture conversation.

## Current Implementation

As of v6.0.6+:
- `migrate-to-v6.sh` tells users to run `/init-context`
- `/init-context` has dual-mode: detects migration state and handles it
- This works but has the naming confusion issue
