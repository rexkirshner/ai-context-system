# v6.0.2 Release Plan

## Overview

Patch release to fix v5.x → v6.0 migration issues discovered during QA testing.

## Problem Summary

Users upgrading from v5.x to v6.0 encounter multiple failures:

1. **v5.x update command breaks mid-execution** - References scripts that v6.0 installer deletes
2. **`/save` corrupts v5.x STATUS.md** - Expects v6.0 format, would destroy existing content
3. **DECISIONS.md format mismatch** - v5.x uses detailed format, v6.0 uses simple format
4. **Version detection fails** - Shows "none" instead of detecting v5.x

## Root Cause

The v5.x `/update-context-system` command has script dependencies. When it downloads v6.0:
1. v6.0 installer deletes `scripts/`, `templates/`, etc.
2. v5.x command continues executing but its dependencies are gone
3. Command fails or completes partially
4. User is left with v6.0 commands but v5.x context file formats
5. Running `/save` would corrupt their STATUS.md

We can't fix the v5.x command retroactively. But we CAN make v6.0 commands resilient to this scenario.

## Solution: Make Commands Format-Aware

### Principle

Commands should detect the format of existing files and either:
1. Migrate them automatically (applying MIGRATIONS.md logic inline)
2. Work with them gracefully
3. Provide clear guidance if manual intervention needed

## Changes for v6.0.2

### 1. Update `/save` to Handle v5.x STATUS.md Format

**File:** `.claude/commands/save.md`

**Current behavior:** Assumes v6.0 format exists, would corrupt v5.x format.

**New behavior:** Detect format and migrate if needed.

Add after "## Steps" or at the beginning of the command:

```markdown
### 0. Detect STATUS.md Format

Before updating, check if `context/STATUS.md` exists and what format it uses.

**v6.0 format indicators:**
- Contains `SchemaVersion: 1`
- Has `## Working Set` section
- Has `## Next Actions` section

**v5.x format indicators:**
- Contains `## Quick Reference` section
- Contains `## Current Phase` or `## Work In Progress`
- Has URL fields or Tech Stack sections
- Missing `SchemaVersion`

**If v5.x format detected:**

1. **Extract key information:**
   - Current objective/focus from any "Objective" or "Current Focus" field
   - Work in progress items
   - Next steps or action items
   - Any blockers

2. **Transform to v6.0 format:**
   ```markdown
   # Status

   SchemaVersion: 1
   LastUpdated: [today's date]
   HeadCommit: [git rev-parse --short HEAD, or N/A]
   Objective: [extracted objective]

   ## Working Set

   - [extracted files being worked on, or TBD]

   ## Next Actions

   - [extracted next steps, or TBD]

   ## Blocked On

   - [extracted blockers, or (None)]
   ```

3. **Report the migration:**
   ```
   ⚠️  Migrated STATUS.md from v5.x to v6.0 format
      Original backed up to: context/STATUS.md.v5-backup
   ```

4. **Continue with normal /save behavior** on the new format.
```

### 2. Update `/save` to Handle v5.x DECISIONS.md Format

**Current behavior:** Appends v6.0 simple format to any existing file.

**New behavior:** Detect format and adapt.

Add to the DECISIONS.md section:

```markdown
### DECISIONS.md Format Detection

**v6.0 format:** Simple entries with Why/Tradeoff/RevisitWhen
**v5.x format:** Detailed entries with Context/Decision/Rationale/Alternatives/Tradeoffs/Consequences/When to Reconsider

**If v5.x format detected:**
- Continue using the v5.x detailed format for new entries
- Do NOT mix formats in the same file
- New entries should follow the existing pattern

**If v6.0 format (or new file):**
- Use the simple v6.0 format
```

### 3. Update `update-context-system` for Robustness

**File:** `.claude/commands/update-context-system.md`

**Changes:**

1. **Better version detection** - Check both `VERSION` (root) and `.claude/VERSION`:
   ```markdown
   ### 1. Check Current Version

   Check for version in this order:
   1. `.claude/VERSION` (v6.0+ location)
   2. `VERSION` (some v5.x installations)
   3. If neither exists, check for v5.x artifacts:
      - `scripts/` directory exists → v5.x
      - `.claude/agents/` exists → v5.x
      - `context/SESSIONS.md` exists → v5.x
   4. If no indicators found, assume fresh install (no version)
   ```

2. **Add recovery section** for failed v5.x upgrades:
   ```markdown
   ### Pre-flight Check: Detect Partial Migration

   Before proceeding, check if a previous v5.x upgrade failed mid-execution:

   **Signs of partial migration:**
   - `.claude/VERSION` shows 6.0.x BUT
   - `context/STATUS.md` has v5.x format (Quick Reference, etc.)
   - OR `scripts/` directory still exists
   - OR `.claude/agents/` still exists

   **If detected:**
   1. Report: "Detected incomplete v5.x → v6.0 migration. Resuming cleanup..."
   2. Skip to Step 6 (Run Migrations) to complete the migration
   3. Do NOT re-download or re-copy command files
   ```

3. **Ensure migration steps are idempotent** - Can be run multiple times safely

### 4. Update MIGRATIONS.md with Recovery Section

**File:** `MIGRATIONS.md`

Add new section after the main migration steps:

```markdown
---

## Recovery: If v5.x Update Failed Mid-Execution

If you ran `/update-context-system` from v5.x and it failed partway through, you may have:
- v6.0 commands installed
- But v5.x context file formats still in place
- And/or leftover v5.x artifacts (scripts/, agents/, etc.)

### Option 1: Let /save Handle It

Simply run `/save`. The v6.0.2+ version will:
1. Detect v5.x STATUS.md format
2. Migrate it to v6.0 format automatically
3. Back up the original

### Option 2: Manual Migration

If /save doesn't work or you prefer manual control:

1. **Verify v6.0 commands are installed:**
   ```bash
   cat .claude/VERSION  # Should show 6.0.x
   ls .claude/commands/  # Should show 8 files
   ```

2. **If commands aren't installed, install them:**
   ```bash
   git clone --depth 1 https://github.com/rexkirshner/ai-context-system.git /tmp/acs
   cp -r /tmp/acs/.claude/commands .claude/
   cp /tmp/acs/.claude/VERSION .claude/
   rm -rf /tmp/acs
   ```

3. **Clean up v5.x artifacts:**
   ```bash
   rm -rf scripts/ templates/ .claude/agents/ .claude/skills/ .claude/schemas/
   rm -f context/SESSIONS.md context/CONTEXT.md
   ```

4. **Manually migrate STATUS.md** following Step 5 above.

5. **Restart Claude Code session** to load new commands.

6. **Run /save** to verify everything works.
```

### 5. Version Bump

- Update `.claude/VERSION` to `6.0.2`
- Update root `VERSION` to `6.0.2`
- Update `CHANGELOG.md` with v6.0.2 section

## Testing Plan

### Test Case 1: Fresh v5.x → v6.0.2 Upgrade
1. Start with a v5.x project
2. Run `/update-context-system`
3. Verify migration completes
4. Run `/save`
5. Verify STATUS.md is in v6.0 format

### Test Case 2: Partial Migration Recovery
1. Simulate failed v5.x upgrade (v6.0 commands + v5.x STATUS.md)
2. Run `/save`
3. Verify STATUS.md is migrated and backed up
4. Verify /save completes successfully

### Test Case 3: Already v6.0 Project
1. Start with v6.0.1 project
2. Run `/update-context-system`
3. Verify no unnecessary migrations
4. Run `/save`
5. Verify normal behavior

### Test Case 4: v5.x DECISIONS.md Format Preservation
1. Start with v5.x project that has detailed DECISIONS.md
2. Upgrade to v6.0.2
3. Run `/save` with a decision to record
4. Verify new entry uses v5.x detailed format (not mixed)
