# v6.0.2 Release Plan

## Overview

Patch release to fix v5.x → v6.0 migration issues. Clean break from legacy system.

## Philosophy

1. **`/save` does ONE thing** — Updates context in v6.0 format. Nothing else.
2. **`update-context-system` handles ALL migration** — Format conversion, cleanup, everything.
3. **No tech debt** — Migrate everything to v6.0 format. Don't preserve old formats.
4. **Clean break** — After upgrade, zero v5.x artifacts remain.

---

## Problem Summary

Users upgrading from v5.x encounter failures:

| Issue | Cause |
|-------|-------|
| v5.x update command breaks | References scripts that v6.0 installer deletes |
| `/save` corrupts STATUS.md | Expects v6.0 format, destroys v5.x content |
| Version detection fails | Looks for `.claude/VERSION` which v5.x doesn't have |
| Mixed formats | v5.x DECISIONS.md format differs from v6.0 |

## Root Cause

When v5.x users run `/update-context-system`:
1. The v5.x command (with script dependencies) executes
2. v6.0 installer deletes `scripts/`, `templates/`, etc.
3. v5.x command breaks mid-execution
4. User left with v6.0 commands but v5.x context formats
5. `/save` fails or corrupts files

---

## Solution

### Principle: Separation of Concerns

| Command | Responsibility |
|---------|----------------|
| `/save` | Update context. v6.0 format only. If v5.x format detected → error with clear guidance. |
| `update-context-system` | All migration: version detection, format conversion, artifact cleanup. |

### `/save` Behavior

**If v5.x STATUS.md format detected:**
```
❌ STATUS.md is in v5.x format.

Run /update-context-system to migrate to v6.0 format first.
```

**Does NOT:**
- Migrate formats
- Clean artifacts
- Handle legacy edge cases

**ONLY:**
- Updates v6.0 format STATUS.md
- Records decisions to v6.0 format DECISIONS.md

### `update-context-system` Behavior

Handles the complete migration by reading and applying MIGRATIONS.md:

1. **Detect current state** (version, format, artifacts)
2. **Backup everything**
3. **Delete all v5.x artifacts**
4. **Install v6.0 commands**
5. **Migrate STATUS.md** to v6.0 format
6. **Migrate DECISIONS.md** to v6.0 format
7. **Verify and report**

## Changes for v6.0.2

### 1. Update `/save` — Add Format Guard

**File:** `.claude/commands/save.md`

Add at the beginning of execution:

```markdown
### Format Check

Before updating, verify `context/STATUS.md` is in v6.0 format.

**v6.0 format required indicators:**
- Contains `SchemaVersion: 1`
- Has `## Working Set` section
- Has `## Next Actions` section

**v5.x format indicators (migration needed):**
- Contains `## Quick Reference`
- Contains `## Current Phase` or `## Work In Progress`
- Has URL fields, Tech Stack sections
- Missing `SchemaVersion`

**If v5.x format detected:**

Stop and report:
```
❌ STATUS.md is in v5.x format.

Run /update-context-system to migrate to v6.0 format first.

This is a one-time migration that will:
- Convert STATUS.md to v6.0 format
- Convert DECISIONS.md to v6.0 format
- Clean up legacy artifacts (scripts/, agents/, etc.)
- Preserve your content in the new structure
```

Do NOT attempt to update the file.
```

### 2. Update `update-context-system` — Robust Migration

**File:** `.claude/commands/update-context-system.md`

#### 2a. Better Version Detection

```markdown
### 1. Detect Current Version

Check in this order:
1. `.claude/VERSION` — v6.0+ location
2. `VERSION` at project root — some v5.x installations

If neither exists, detect v5.x by artifacts:
- `scripts/` directory → v5.x
- `.claude/agents/` directory → v5.x
- `context/SESSIONS.md` → v5.x
- `## Quick Reference` in STATUS.md → v5.x

If no version and no v5.x indicators → fresh install (no migration needed).
```

#### 2b. Partial Migration Detection

```markdown
### 2. Detect Partial Migration

Check for incomplete v5.x → v6.0 upgrade:

**Signs of partial migration:**
- `.claude/VERSION` exists (6.0.x) BUT any of:
  - `context/STATUS.md` has v5.x format
  - `scripts/` directory still exists
  - `.claude/agents/` still exists
  - `context/SESSIONS.md` still exists

**If detected:**
Report: "Detected incomplete v5.x → v6.0 migration. Resuming..."
Skip download, proceed directly to migration steps.
```

#### 2c. DECISIONS.md Migration

```markdown
### 6c. Migrate DECISIONS.md Format

If DECISIONS.md exists with v5.x detailed format, transform each entry.

**v5.x format (detailed):**
```markdown
## 2026-01-24: Chose SQLite
Context: [background]
Decision: [what was decided]
Rationale: [why]
Alternatives Considered: [options]
Tradeoffs Accepted: [downsides]
Consequences: [implications]
When to Reconsider: [trigger]
```

**Transform to v6.0 format (simple):**
```markdown
## 2026-01-24: [DB] Chose SQLite
Why: [extract from Rationale, keep concise]
Tradeoff: [extract from Tradeoffs Accepted]
RevisitWhen: [extract from When to Reconsider]
```

**Guidelines:**
- Infer [Area] prefix from context (DB, API, Auth, UI, Infra, Deps, Arch, Perf)
- Condense Rationale to 1-2 sentences for Why
- Keep the essence, drop the verbosity
- Historical detail preserved in git history
```

### 3. Update MIGRATIONS.md — Recovery Section

**File:** `MIGRATIONS.md`

Add section:

```markdown
---

## Recovery: If v5.x Upgrade Failed

If you ran `/update-context-system` from v5.x and it failed partway through:

### Symptoms
- `/save` errors with "STATUS.md is in v5.x format"
- Mix of v6.0 commands and v5.x artifacts
- Old `scripts/` or `.claude/agents/` directories still exist

### Solution

Run `/update-context-system` again. The v6.0.2+ version will:
1. Detect the partial migration state
2. Resume cleanup and format conversion
3. Complete the migration properly

### Manual Recovery (if command still fails)

1. **Download fresh v6.0 commands:**
   ```bash
   git clone --depth 1 https://github.com/rexkirshner/ai-context-system.git /tmp/acs
   rm -rf .claude/commands/
   cp -r /tmp/acs/.claude/commands .claude/
   cp /tmp/acs/.claude/VERSION .claude/
   rm -rf /tmp/acs
   ```

2. **Restart Claude Code session** (exit and reopen)

3. **Run `/update-context-system`** — it will detect v5.x artifacts and migrate
```
