# v5.1.2 Implementation Plan - Settings File Conflict Fix

**Status:** Planning
**Created:** 2026-01-18
**Based on:** Real-world feedback from Custom Doodle and Video Gallery projects

---

## Overview

This patch release fixes a critical bug where ACS creates `.claude/settings.json` with a custom schema that conflicts with Claude Code's expected schema, causing Claude Code to reject all project settings.

### Release Scope

- **1 Bug Fix** - Settings file schema conflict
- **0 Breaking Changes** - Fully backward compatible
- **Estimated Effort** - 2-3 hours implementation + testing

### The Problem

ACS creates `.claude/settings.json` with:
```json
{
  "$schema": "https://acs.rexkirshner.com/schemas/settings.json",
  "hooks": { "enabled": true, "timeout": 2000, "onFailure": "warn" },
  "profiles": { ... }
}
```

But Claude Code reserves `.claude/settings.json` for its own schema and rejects files that don't conform:
```
Settings Error
.claude/settings.json
  ├ $schema: Invalid value. Expected one of:
  │ "https://json.schemastore.org/claude-code-settings.json"
  └ hooks
    ├ enabled: Invalid key in record
    ├ onFailure: Invalid key in record
    └ timeout: Invalid key in record
```

**Impact:** Claude Code ignores ALL project settings when this file is present.

## Phase 2: Fix Existing Installations (Migration)

### 2.1 Add Migration Logic to update-context-system.md

**Location:** `.claude/commands/update-context-system.md`

**Add a migration step that:**
1. Checks if `.claude/settings.json` exists
2. If using old ACS schema, either removes or renames it
3. Warns user about the change

**Add after backup step:**
```bash
# Step X: Migrate settings.json (v5.1.2 fix)
if [ -f ".claude/settings.json" ]; then
  # Check if it's our problematic file (has our custom schema)
  if grep -q "acs.rexkirshner.com/schemas/settings.json" ".claude/settings.json" 2>/dev/null; then
    echo "⚠️  Migrating .claude/settings.json (conflicts with Claude Code)"

    # Option A: Remove
    rm -f ".claude/settings.json"
    echo "   ✅ Removed conflicting settings.json"
    echo "   Note: ACS settings moved to context/.context-config.json"

    # Option B: Rename (alternative)
    # mv ".claude/settings.json" ".claude/acs-settings.json"
    # echo "   ✅ Renamed to .claude/acs-settings.json"
  fi
fi
```

**Acceptance Criteria:**
- [ ] Migration step added to update-context-system.md
- [ ] Only migrates files with ACS schema (not user's Claude Code settings)
- [ ] Clear message to user about what changed
