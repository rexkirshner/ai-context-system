# v5.0.1 Release Planning Document

**Created:** 2026-01-14
**Updated:** 2026-01-14 (incorporated external review feedback)

**Status:** Planning Complete - Ready for Implementation

---

## Executive Summary

v5.0.0 introduced the agent-based code review architecture, but critical bugs prevent the system from working correctly:

1. **Installer doesn't download v5.0.0 directories** - agents, schemas, skills, hooks are missing
2. **Session numbering uses COUNT instead of MAX** - creates duplicate sessions after archiving
3. **Scripts use GNU-specific syntax** - breaks on macOS (BSD tools)
4. **Validation checks for renamed commands** - false failures on correct installations

This document outlines a systematic fix plan prioritizing:
- **Maintainability**: Centralized helpers, no scattered platform-specific code
- **Portability**: Works on macOS and Linux without modification
- **Testability**: Every fix has automated verification
- **Upgradability**: VERSION file as single source of truth, reproducible installs

---

## Guiding Principles

### 1. No Bandaids
Every fix should address the root cause. If we find ourselves writing platform-specific code in multiple places, we create a helper instead.

### 2. Portable by Default
All new code must work on both macOS (BSD tools) and Linux (GNU tools). Use POSIX where possible, helpers where not.

### 3. Objectively Verifiable
Every task has a verification command that returns a deterministic, checkable result. No "looks right" - only "passes/fails".

### 4. Test Everything
Every fix gets an automated test. Tests prevent regressions and document expected behavior.

### 5. Single Source of Truth
- VERSION file for version numbers
- Helpers for platform-specific operations
- Templates for file formats

### Task 0.1: Create `inplace_sed()` helper

**Problem:** `sed -i` works differently on macOS vs Linux:
- Linux: `sed -i 's/a/b/' file`
- macOS: `sed -i '' 's/a/b/' file`

**Solution:** Centralized helper that detects platform and uses correct syntax.

**File:** `scripts/common-functions.sh`

**Implementation:**
```bash
# =============================================================================
# Platform-Portable Helpers (v5.0.1)
# =============================================================================

# In-place sed that works on both macOS (BSD) and Linux (GNU)
#
# Usage:
#   inplace_sed 's/old/new/' file.txt
#   inplace_sed 's/old/new/g' file.txt
#
# Args:
#   $1 - sed expression
#   $2 - file to modify
#
# Returns:
#   0 on success, 1 on failure
#
# Example:
#   inplace_sed 's/foo/bar/g' config.txt
#
inplace_sed() {
  local expression="$1"
  local file="$2"

  if [ -z "$expression" ] || [ -z "$file" ]; then
    log_error "inplace_sed: requires expression and file arguments"
    return 1
  fi

  if [ ! -f "$file" ]; then
    log_error "inplace_sed: file not found: $file"
    return 1
  fi

  # Detect sed variant and use appropriate syntax
  if sed --version 2>&1 | grep -q GNU; then
    # GNU sed (Linux)
    sed -i "$expression" "$file"
  else
    # BSD sed (macOS)
    sed -i '' "$expression" "$file"
  fi
}
```

### Task 0.2: Create `hash_file()` helper

**Problem:** Hash commands differ by platform:
- Linux: `md5sum`, `sha256sum`
- macOS: `md5`, `shasum -a 256`

**Solution:** Centralized helper that finds available hash command.

**File:** `scripts/common-functions.sh`

**Implementation:**
```bash
# Compute SHA-256 hash of a file (portable across macOS/Linux)
#
# Usage:
#   hash=$(hash_file /path/to/file)
#
# Args:
#   $1 - file to hash
#
# Returns:
#   Prints SHA-256 hash (64 hex characters) to stdout
#   Returns 1 if file not found or no hash command available
#
# Example:
#   if [ "$(hash_file a.txt)" = "$(hash_file b.txt)" ]; then
#     echo "Files are identical"
#   fi
#
hash_file() {
  local file="$1"

  if [ -z "$file" ]; then
    log_error "hash_file: requires file argument"
    return 1
  fi

  if [ ! -f "$file" ]; then
    log_error "hash_file: file not found: $file"
    return 1
  fi

  # Try hash commands in order of preference
  if command -v sha256sum &>/dev/null; then
    # Linux (GNU coreutils)
    sha256sum "$file" | cut -d' ' -f1
  elif command -v shasum &>/dev/null; then
    # macOS / BSD
    shasum -a 256 "$file" | cut -d' ' -f1
  elif command -v openssl &>/dev/null; then
    # Fallback: openssl (available on most systems)
    openssl dgst -sha256 "$file" | sed 's/.*= //'
  else
    log_error "hash_file: no hash command available (need sha256sum, shasum, or openssl)"
    return 1
  fi
}

# Compare two files by hash (returns 0 if identical, 1 if different)
#
# Usage:
#   if files_identical file1.txt file2.txt; then
#     echo "Same content"
#   fi
#
files_identical() {
  local file1="$1"
  local file2="$2"

  [ "$(hash_file "$file1")" = "$(hash_file "$file2")" ]
}
```

### Task 0.3: Create `json_validate()` helper

**Problem:** JSON validation tools differ:
- Some systems have `jq`
- Some have Python 3
- Need graceful fallback

**Solution:** Helper that tries available JSON validators.

**File:** `scripts/common-functions.sh`

**Implementation:**
```bash
# Validate JSON file syntax (portable across systems)
#
# Usage:
#   if json_validate config.json; then
#     echo "Valid JSON"
#   fi
#
# Args:
#   $1 - JSON file to validate
#
# Returns:
#   0 if valid JSON, 1 if invalid or file not found
#
# Note: Tries jq first, then python3, then python
#
json_validate() {
  local file="$1"

  if [ -z "$file" ]; then
    log_error "json_validate: requires file argument"
    return 1
  fi

  if [ ! -f "$file" ]; then
    log_error "json_validate: file not found: $file"
    return 1
  fi

  # Try validators in order of preference
  if command -v jq &>/dev/null; then
    jq empty "$file" 2>/dev/null
  elif command -v python3 &>/dev/null; then
    python3 -c "import json; json.load(open('$file'))" 2>/dev/null
  elif command -v python &>/dev/null; then
    python -c "import json; json.load(open('$file'))" 2>/dev/null
  else
    # No validator available - assume valid (best effort)
    log_warn "json_validate: no JSON validator available (install jq for best results)"
    return 0
  fi
}
```

### Task 0.4: Create `count_files()` helper

**Problem:** File counting with `ls | wc -l` is fragile (varies by platform, includes directory entries).

**Solution:** Deterministic file counter using `find`.

**File:** `scripts/common-functions.sh`

**Implementation:**
```bash
# Count files matching a pattern in a directory (deterministic)
#
# Usage:
#   count=$(count_files /path/to/dir "*.md")
#   count=$(count_files /path/to/dir "*.json")
#
# Args:
#   $1 - directory to search
#   $2 - filename pattern (glob)
#
# Returns:
#   Prints count to stdout (integer)
#   Returns 1 if directory not found
#
# Example:
#   agent_count=$(count_files .claude/agents "*.md")
#   [ "$agent_count" -eq 12 ] || echo "Expected 12 agents"
#
count_files() {
  local dir="$1"
  local pattern="$2"

  if [ -z "$dir" ]; then
    log_error "count_files: requires directory argument"
    return 1
  fi

  if [ ! -d "$dir" ]; then
    echo "0"
    return 0
  fi

  # Default pattern matches all files
  pattern="${pattern:-*}"

  # Use find for deterministic, portable counting
  # -maxdepth 1: don't recurse
  # -type f: only files (not directories)
  # -name: match pattern
  find "$dir" -maxdepth 1 -type f -name "$pattern" 2>/dev/null | wc -l | tr -d ' '
}
```

```bash
# =============================================================================
# Step 0: Parse command line flags

NON_INTERACTIVE=false
INSTALL_VERSION=""

while [[ $# -gt 0 ]]; do
  case $1 in
    --yes|-y|--force)
      NON_INTERACTIVE=true
      shift
      ;;
    --version)
      INSTALL_VERSION="$2"

    --version=*)
      INSTALL_VERSION="${1#*=}"
      shift
      ;;
    *)
      shift
      ;;

# If specific version requested, use tag URL
if [ -n "$INSTALL_VERSION" ]; then
  RAW_URL="https://raw.githubusercontent.com/rexkirshner/ai-context-system/refs/tags/v${INSTALL_VERSION}"

fi
```

### Task 2.1: Rewrite get_next_session_number()


**New (correct):**
```bash
# Get the next session number (MAX + 1, not COUNT + 1)
#
# Handles gaps from archiving and non-sequential session numbers.
# Supports both session header formats:
#   - Pipe format: "## Session N | DATE | TITLE"
#   - Dash format: "## Session N - DATE"
#
# Usage:
#   next=$(get_next_session_number)
#   next=$(get_next_session_number "context")
#
# Args:
#   $1 - context directory (optional, default: "context")
#
# Returns:
#   Prints next session number to stdout (MAX existing + 1)
#
# Example:
#   If sessions 1, 2, 3, 40, 41, 44 exist, returns 45 (not 7)
#
get_next_session_number() {
  local context_dir="${1:-context}"
  local sessions_file="$context_dir/SESSIONS.md"

  # No file = start at 1
  if [ ! -f "$sessions_file" ]; then
    echo "1"
    return 0
  fi

  # Find the maximum session number
  # 1. Stop before "## Example" sections (template content)
  # 2. Match "## Session N" where N is a number
  # 3. Exclude template references
  # 4. Extract just the number
  # 5. Sort numerically and take the largest
  local max_session
  max_session=$(
    sed -n '1,/^## Example/p' "$sessions_file" 2>/dev/null | \
    grep -E "^## Session [0-9]+" | \
    grep -v -i "Template" | \
    sed -E 's/^## Session ([0-9]+).*/\1/' | \
    sort -n | \
    tail -1
  )

  # Default to 0 if no sessions found or invalid result
  if [ -z "$max_session" ] || ! [[ "$max_session" =~ ^[0-9]+$ ]]; then
    max_session=0
  fi

  echo $((max_session + 1))
}
```

### Task 5.3: Improve feedback file replacement logic

**Problem:** Only checks for date-formatted entries, may delete modified files.

**File:** `.claude/commands/update-context-system.md` (Step 2.5)

**New logic using hash comparison:**
```bash
# Check if feedback file has been modified from template
if [ -f "context/context-feedback.md" ] && [ -f "templates/context-feedback.template.md" ]; then
  source scripts/common-functions.sh

  if ! files_identical "context/context-feedback.md" "templates/context-feedback.template.md"; then
    # File has been modified - archive it
    ARCHIVE_DATE=$(date +%Y-%m-%d)
    ARCHIVE_FILE="context/context-feedback-archive-${ARCHIVE_DATE}.md"

    # Don't overwrite existing archive
    if [ -f "$ARCHIVE_FILE" ]; then
      ARCHIVE_FILE="context/context-feedback-archive-${ARCHIVE_DATE}-$(date +%H%M%S).md"
    fi

    cp "context/context-feedback.md" "$ARCHIVE_FILE"
    log_info "Archived modified feedback file to $ARCHIVE_FILE"
  fi
fi
```

**Checkpoint 5.3:**
