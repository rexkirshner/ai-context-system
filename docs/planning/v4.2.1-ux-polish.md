## Issues from User Feedback

### Issue 1: Update Notice Shows During Update (Priority: High)

**Source:** context-feedback.md - "common-functions.sh Auto-Shows Update Notice"

**Problem:** When sourcing `scripts/common-functions.sh` during `/update-context-system`, it displays:

```
💡 Update available: v4.0.2 → v4.2.0
   Run /update-context-system to upgrade
```

This is confusing because the user is ALREADY running `/update-context-system`.

**Location:** `scripts/common-functions.sh:514`

**Fix:** Add environment variable check to suppress notice during updates:

```bash
# At start of /update-context-system (Step 0)
export ACS_UPDATING=true

# In common-functions.sh check_for_updates() function
check_for_updates() {
  # Skip if we're already updating
  if [ "$ACS_UPDATING" = "true" ]; then
    return 0
  fi
  # ... existing logic
}
```

**Testing:**
- Run `/update-context-system` and verify no "Run /update-context-system" message appears
- Run `/review-context` and verify update notice DOES appear (when outdated)

### Issue 2: Outdated "What's New" Documentation (Priority: Medium)

**Source:** context-feedback.md - '"What's New" Section Hardcoded'

**Problem:** User reported seeing "What's New in v4.0.0" during upgrade to v4.2.0.

**Investigation:**
- `update-context-system.md` Step 3 was fixed in v4.1.0 to link to CHANGELOG
- However, `.claude/docs/update-guide.md` still shows "What's New in v3.3.0" (line 7)
- This file may be displayed during updates or referenced by users

**Locations to check:**
1. `.claude/docs/update-guide.md` - Line 7: "## 🎉 What's New in v3.3.0"
2. Any other hardcoded version strings

**Fix Options:**

**Option A (Minimal):** Update the heading to be version-agnostic
```markdown
## 🎉 Recent Updates

See [CHANGELOG.md](https://github.com/rexkirshner/ai-context-system/blob/main/CHANGELOG.md) for full version history.
```

**Option B (Remove file):** This guide is largely outdated (references v3.x features). Consider:
1. Deprecating `.claude/docs/update-guide.md`
2. Pointing users to CHANGELOG.md and migration docs instead

**Recommendation:** Option B - the file is 800+ lines of outdated content. Better to remove than maintain.

**Testing:**
- Grep for any remaining hardcoded "What's New in v" strings
- Verify update flow doesn't reference removed file
