# v5.1.0 Planning: Context System Refinements

**Created:** 2026-01-14
**Status:** Planning
**Target:** Next minor release after v5.0.1 stabilizes

---

## Executive Summary

v5.1.0 focuses on addressing structural feedback from production deployments. The theme is **"right-sizing"** - ensuring each file serves its purpose without becoming unwieldy.

Key goals:
1. Manage file growth (archiving, splitting guidance)
2. Clarify file purposes and reduce overlap
3. Improve AI agent efficiency with large projects

---

## Feedback Summary

### What's Working Well
- STATUS.md design (dashboard at top, scannable)
- Layered approach (quick scan → deep dive)
- Separation of concerns (decisions vs sessions vs status)

### What Needs Improvement
- File growth is unmanaged (DECISIONS.md, SESSIONS.md grow forever)
- No "lite" mode for quick context loading
- Too many files (7-11) can overwhelm
- Unclear what's "core" vs "optional"
- ARCHITECTURE.md becomes book-length in complex projects

---

## Proposed Changes

### Phase 1: File Growth Management

#### 1.1 DECISIONS.md Archiving

**Problem:** DECISIONS.md grows indefinitely. Old decisions clutter the file.

**Solution:** Mirror SESSIONS.md archiving approach:
- Add `scripts/archive-decisions-helper.sh`
- Archive when >100 decisions
- Keep most recent 50 in main file
- Archive superseded decisions automatically

**Verification Checkpoint:**
```bash
# Test archiving with mock file
./scripts/archive-decisions-helper.sh --dry-run
# Should show what would be archived without making changes
```

**Files:**
- NEW: `scripts/archive-decisions-helper.sh`
- MOD: `.claude/commands/save-full.md` (add archiving prompt)
- MOD: `templates/DECISIONS.template.md` (add archiving section)

### Phase 2: File Purpose Clarification

#### 2.1 Core vs Optional File Documentation

**Problem:** Template creates all files, but not all are needed. Users unsure what's required.

**Solution:** Clear documentation in templates and /init-context:

**Core Files (always create):**
1. `CLAUDE.md` - AI entry point (root)
2. `context/CONTEXT.md` - Project orientation
3. `context/STATUS.md` - Current state dashboard
4. `context/SESSIONS.md` - Session history

**Standard Files (create if needed):**
5. `context/DECISIONS.md` - Decision log (when making architectural choices)

**Optional Files (create on demand):**
6. `context/ARCHITECTURE.md` - Deep technical docs (complex projects)
7. `context/CODE_STYLE.md` - Style beyond linter config
8. `context/KNOWN_ISSUES.md` - Blockers and gotchas
9. `context/PRD.md` - Product requirements

**Verification Checkpoint:**
```bash
# /init-context should only create core files by default
./test-init-creates-core-only.sh
# Should create 4-5 files, not 9
```

**Files:**
- MOD: `.claude/commands/init-context.md`
- MOD: `templates/*.md` (add "Core/Optional" badges)
- NEW: `.claude/docs/FILE_PURPOSES.md`

---

#### 2.2 CONTEXT.md vs README.md Clarification

**Problem:** Overlap between CONTEXT.md and README.md confuses users.

**Solution:** Document distinct purposes:

| File | Audience | Purpose | Updates |
|------|----------|---------|---------|
| README.md | Humans (GitHub) | Project intro, setup, badges | Rarely |
| CONTEXT.md | AI agents | Orientation for takeover | Each session |

**Verification Checkpoint:**
```bash
# Documentation should explain the difference
grep -q "README.md" .claude/docs/FILE_PURPOSES.md
# Should find README.md mentioned with distinction
```

**Files:**
- NEW: `.claude/docs/FILE_PURPOSES.md`
- MOD: `templates/CONTEXT.template.md` (add note about README.md)

---

#### 2.3 ARCHITECTURE.md Size Guidance

**Problem:** ARCHITECTURE.md grows to 1500+ lines, becoming unwieldy.

**Solution:** Add guidance for splitting large files:

```markdown
## When to Split ARCHITECTURE.md

If ARCHITECTURE.md exceeds 500 lines, consider:

context/ARCHITECTURE.md (overview, ~300 lines)
├── System diagram
├── Key patterns summary
├── Component overview
└── Links to deep dives

docs/architecture/ (deep dives)
├── authentication.md
├── database-design.md
├── api-contracts.md
└── deployment.md
```

**Verification Checkpoint:**
```bash
# Template should include splitting guidance
grep -q "exceed.*500\|split\|docs/architecture" templates/ARCHITECTURE.template.md
```

**Files:**
- MOD: `templates/ARCHITECTURE.template.md`

### Phase 3: Efficiency Improvements

#### 3.1 Quick Context Mode

**Problem:** Sometimes AI just needs current state, not full history.

**Solution:** Add `/review --quick` mode that loads only:
- STATUS.md Quick Reference section
- Last session from SESSIONS.md
- Active tasks only

**Implementation:**
```bash
# In review-context.md, add flag handling:
if [ "$QUICK_MODE" = "true" ]; then
  # Load minimal context
  # Skip historical data
fi
```

**Verification Checkpoint:**
```bash
# Quick mode should be significantly faster
time claude "/review-context --quick"
# Should complete in <5 seconds for any project size
```

**Files:**
- MOD: `.claude/commands/review-context.md`
- MOD: `scripts/common-functions.sh` (add quick loading helpers)

---

#### 3.2 Archived Sessions Location

**Problem:** Archived sessions stay in context/ folder, cluttering it.

**Solution:** Move archives to dedicated location:

```
context/
├── SESSIONS.md (current)
└── .sessions-archive/
    ├── sessions-001-050.md
    ├── sessions-051-100.md
    └── ...
```

**Verification Checkpoint:**
```bash
# After archiving, context/ should have fewer files
ls context/*.md | wc -l
# Should be ≤10 even for mature projects
```

**Files:**
- MOD: `scripts/archive-sessions-helper.sh`
- MOD: `.gitignore` (ensure archives are tracked)
