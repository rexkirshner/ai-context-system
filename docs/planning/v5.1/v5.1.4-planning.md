# v5.1.4 Implementation Plan - Library Adoption Advisor

**Status:** Planning
**Created:** 2026-01-20
**Based on:** Feature originally planned for v5.2.0 (FEAT-8), prioritized for earlier release

---

## Overview

This patch release adds a new code review specialist agent that identifies opportunities to replace homegrown implementations with battle-tested libraries.

### Release Scope

- **1 New Agent** - Library Adoption Advisor (`library-advisor.md`)
- **1 Command Update** - Add `--libraries` flag to `/code-review`
- **0 Breaking Changes** - Fully backward compatible
- **Estimated Effort** - 4-6 hours implementation + testing

### Why v5.1.4 Instead of v5.2.0?

This feature is:
- Self-contained (single agent + flag)
- High value (helps users leverage proven solutions)
- Low risk (additive only, no changes to existing behavior)
- Independent of other v5.2.0 features

### 1.2 Define Detection Patterns

**What the agent scans for:**

| Pattern | Homegrown Sign | Recommended Libraries |
|---------|---------------|----------------------|
| Date manipulation | Manual string formatting, timezone math | date-fns, dayjs, luxon |
| HTTP client | Custom fetch wrappers, retry logic | axios, ky, got |
| Validation | Manual if/else chains, regex checks | zod, yup, joi, valibot |
| State management | Custom pub/sub, global objects | zustand, jotai, redux-toolkit |
| Retry logic | Custom while loops with delays | p-retry, async-retry |
| Debounce/throttle | Custom setTimeout patterns | lodash-es, throttle-debounce |
| Deep clone | JSON.parse(JSON.stringify()) | structuredClone, lodash |
| UUID generation | Math.random() patterns | uuid, nanoid |
| Encryption/hashing | Custom implementations | crypto-js, bcrypt, argon2 |
| Query strings | Manual parsing/building | qs, query-string |
| Markdown parsing | Regex-based parsing | marked, remark, markdown-it |

**Anti-Patterns to Detect:**
- Hand-rolled authentication flows
- Custom ORM/query builders when Prisma/Drizzle exist
- Manual SQL sanitization instead of parameterized queries
- Custom test utilities when testing-library exists
- Bespoke form handling instead of react-hook-form/formik

**Acceptance Criteria:**
- [ ] All 11 pattern categories documented in agent file
- [ ] Anti-patterns section included
- [ ] Each pattern has detection heuristics

---

### 1.3 Define Output Schema

**Each finding includes:**
```json
{
  "id": "LIB-001",
  "type": "individual",
  "severity": "medium",
  "category": "library-adoption",
  "title": "Replace custom date formatting with date-fns",
  "file": "src/utils/date.ts",
  "line": 15,
  "currentApproach": {
    "description": "Custom date formatting using string manipulation",
    "linesOfCode": 47,
    "complexity": "High - handles edge cases poorly"
  },
  "recommendation": {
    "library": "date-fns",
    "version": "^2.30.0",
    "documentation": "https://date-fns.org/docs/format"
  },
  "impact": {
    "codeReduction": "~45 lines removed",
    "reliability": "Battle-tested with 40M+ weekly downloads",
    "maintenance": "No custom code to maintain"
  },
  "downsides": {
    "bundleSize": "+6KB (tree-shakeable)",
    "learningCurve": "Low - familiar API",
    "migration": "Need to update 12 call sites"
  },
  "difficulty": "easy",
  "effortEstimate": "2-4 hours",
  "priority": "recommended"
}
```

**Difficulty Ratings:**
| Difficulty | Definition |
|------------|------------|
| **Easy** | Drop-in replacement, < 2 hours |
| **Medium** | Moderate refactoring, 2-8 hours |
| **Hard** | Significant refactoring, > 1 day |

**Priority Levels:**
| Priority | Definition |
|----------|------------|
| **Recommended** | Clear improvement, should adopt |
| **Consider** | Good option, evaluate tradeoffs |
| **Optional** | Nice to have, low priority |

**Acceptance Criteria:**
- [ ] Output schema documented in agent file
- [ ] Matches audit-finding.json schema structure
- [ ] All fields have clear descriptions
