# v2.2.1 - Organization & Structural Neatness

**Philosophy:** "A place for everything, everything in its place"

**Purpose:** Make the Claude Context System actively promote and enforce project organization, ensuring documentation and files are properly filed and maintained.

**Target:** 2-3 weeks after v2.2.0
**Type:** Enhancement release (non-breaking)

---

## Core Problem

Projects using the Claude Context System accumulate clutter over time:

**Documentation Sprawl:**
```
project-root/
├── README.md
├── NOTES.md                    # Random notes
├── IMPLEMENTATION_PLAN.md      # Old plan
├── PROPOSAL.md                 # Another old plan
├── MILESTONE-1.md              # Completed milestone
├── ANALYSIS.md                 # Random analysis
├── THOUGHTS.md                 # More random notes
├── backend/
│   └── BACKEND_NOTES.md        # Domain-specific notes in wrong place
└── context/
    ├── CONTEXT.md
    └── STATUS.md
```

**Result:**
- Hard to find things
- Unclear what's current vs. historical
- No consistent structure
- Professional projects look messy
- Cognitive load from disorganization

---

## The Solution: Enforced Organization Philosophy

### Core Principle

**Active Files vs. Historical Files**

- **Active** - Currently needed, frequently updated → Keep in root or designated folders
- **Historical** - Completed work, old plans → Archive systematically
- **Permanent** - Long-term reference → Organized in docs/

### The Folder Structure

```
project-root/
├── README.md                   # Project overview (permanent)
├── SECURITY.md                 # Security policy (permanent)
├── CONTRIBUTING.md             # Contribution guide (permanent)
│
├── context/                    # Claude Context System (active)
│   ├── CONTEXT.md
│   ├── STATUS.md
│   ├── SESSIONS.md
│   ├── DECISIONS.md
│   └── .context-config.json
│
├── docs/                       # Organized documentation (permanent)
│   ├── setup/
│   │   ├── installation.md
│   │   └── configuration.md
│   ├── development/
│   │   ├── local-setup.md
│   │   └── testing.md
│   ├── architecture/
│   │   ├── overview.md
│   │   └── data-flow.md
│   └── api/
│       ├── endpoints.md
│       └── authentication.md
│
├── artifacts/                  # Historical work (archived)
│   ├── milestones/
│   │   ├── milestone-1-auth-complete.md
│   │   └── milestone-2-api-launch.md
│   ├── planning/
│   │   ├── 2025-01-initial-proposal.md
│   │   └── 2025-03-feature-analysis.md
│   ├── reviews/
│   │   ├── 2025-02-15-code-review.md
│   │   └── 2025-04-01-security-audit.md
│   └── research/
│       ├── database-comparison.md
│       └── framework-evaluation.md
│
└── [source code directories]
    ├── src/
    ├── tests/
    └── ...
```

**Rules:**
- Root: Only permanent/essential docs (README, SECURITY, CONTRIBUTING)
- context/: Active context system files only
- docs/: Organized by topic, permanent reference
- artifacts/: Dated, categorized historical work
- Source dirs: No documentation (belongs in docs/ or artifacts/)

### Feature 1: Organization Validation (in /validate-context)

**Add new validation step: File Organization Check**

```bash
### Step 2.8: File Organization Validation (v2.2.1)

**Purpose:** Ensure project maintains structural neatness

echo "Checking file organization..."

# Check for documentation sprawl in root
ROOT_DOCS=$(find . -maxdepth 1 -name "*.md" ! -name "README.md" ! -name "SECURITY.md" ! -name "CONTRIBUTING.md" ! -name "LICENSE.md" ! -name "CHANGELOG.md" | wc -l)

if [ "$ROOT_DOCS" -gt 0 ]; then
  echo "⚠️  Documentation sprawl detected in project root:"
  echo ""
  find . -maxdepth 1 -name "*.md" ! -name "README.md" ! -name "SECURITY.md" ! -name "CONTRIBUTING.md" ! -name "LICENSE.md" ! -name "CHANGELOG.md"
  echo ""
  echo "Recommendation: Move these files to appropriate locations:"
  echo "  - Active planning → docs/planning/"
  echo "  - Completed milestones → artifacts/milestones/"
  echo "  - Old proposals → artifacts/planning/"
  echo "  - Meeting notes → artifacts/notes/"
  echo "  - Architecture docs → docs/architecture/"
  echo ""
  ORGANIZATION_SCORE=$((ORGANIZATION_SCORE - 10))
fi

# Check for docs in source directories
SOURCE_DOCS=$(find src -name "*.md" 2>/dev/null | wc -l)
if [ "$SOURCE_DOCS" -gt 0 ]; then
  echo "⚠️  Documentation found in source directories:"
  find src -name "*.md"
  echo ""
  echo "Recommendation: Move to docs/ folder"
  ORGANIZATION_SCORE=$((ORGANIZATION_SCORE - 5))
fi

# Check if artifacts/ exists for historical work
if [ ! -d "artifacts" ] && [ "$ROOT_DOCS" -gt 3 ]; then
  echo "💡 Suggestion: Create artifacts/ folder for historical work"
  echo "   mkdir -p artifacts/{milestones,planning,reviews,research}"
fi

# Check if docs/ exists for permanent documentation
if [ ! -d "docs" ] && [ "$(find . -name "*.md" | wc -l)" -gt 10 ]; then
  echo "💡 Suggestion: Create docs/ folder for organized documentation"
  echo "   mkdir -p docs/{setup,development,architecture,api}"
fi

echo "Organization score: $ORGANIZATION_SCORE/100"
```

# /organize-docs Command

**Interactive documentation cleanup** - Helps file documents in appropriate locations.

## Execution Steps

### Step 1: Scan for Disorganized Files

```bash
echo "Scanning for files to organize..."

# Find loose .md files in root (exclude allowed ones)
LOOSE_FILES=$(find . -maxdepth 1 -name "*.md" \
  ! -name "README.md" \
  ! -name "SECURITY.md" \
  ! -name "CONTRIBUTING.md" \
  ! -name "LICENSE.md" \
  ! -name "CHANGELOG.md")

# Find .md files in source directories
SOURCE_DOCS=$(find src backend frontend -name "*.md" 2>/dev/null)

# Combine results
ALL_TO_ORGANIZE="$LOOSE_FILES $SOURCE_DOCS"

if [ -z "$ALL_TO_ORGANIZE" ]; then
  echo "✅ Project is well-organized! No loose files found."
  exit 0
fi

echo "Found $(echo $ALL_TO_ORGANIZE | wc -w) files to organize"
```

### Step 2: Analyze File Types

For each file, determine category:

```bash
categorize_file() {
  local file=$1
  local content=$(head -50 "$file")

  # Check content for keywords
  if echo "$content" | grep -qi "milestone\|completed\|done"; then
    echo "milestone"
  elif echo "$content" | grep -qi "proposal\|plan\|roadmap\|spec"; then
    echo "planning"
  elif echo "$content" | grep -qi "review\|audit\|analysis"; then
    echo "review"
  elif echo "$content" | grep -qi "research\|comparison\|evaluation"; then
    echo "research"
  elif echo "$content" | grep -qi "setup\|install\|configuration"; then
    echo "setup"
  elif echo "$content" | grep -qi "architecture\|design\|structure"; then
    echo "architecture"
  elif echo "$content" | grep -qi "api\|endpoint\|route"; then
    echo "api"
  else
    echo "general"
  fi
}
```

```markdown
# Project Organization Guidelines

**Philosophy:** "A place for everything, everything in its place"

## Folder Structure

### Root Directory (Minimal)
**Only these files belong in root:**
- README.md - Project overview
- SECURITY.md - Security policy
- CONTRIBUTING.md - Contribution guidelines
- LICENSE.md - License
- CHANGELOG.md - Version history

**Everything else goes in organized folders.**

### context/ - Active Context System
- CONTEXT.md - Project orientation
- STATUS.md - Current state
- SESSIONS.md - Session history
- DECISIONS.md - Decision log
- .context-config.json - Configuration

### docs/ - Permanent Documentation
Organized by topic, updated as needed:

- docs/setup/ - Installation, configuration
- docs/development/ - Development guides
- docs/architecture/ - System design
- docs/api/ - API documentation

### artifacts/ - Historical Work
Dated files, never deleted, rarely updated:

- artifacts/milestones/ - Completed milestones
- artifacts/planning/ - Old proposals, plans
- artifacts/reviews/ - Code reviews, audits
- artifacts/research/ - Research, comparisons

## Naming Conventions

### Dates
Use ISO format for dated files: `YYYY-MM-DD-description.md`
- ✅ `2025-10-20-api-proposal.md`
- ❌ `api-proposal-oct-20.md`

### Milestones
Include date and brief description:
- ✅ `2025-10-milestone-1-auth-complete.md`
- ❌ `milestone1.md`

### Categories
Use clear, descriptive names:
- ✅ `database-comparison-analysis.md`
- ❌ `db-stuff.md`

## When to Organize

### Daily (Quick)
- Keep root clean
- File completed work immediately

### Weekly (5 min)
- Review loose files
- Move old plans to artifacts/

### Monthly (15 min)
- Run /organize-docs
- Archive completed milestones
- Clean up docs/

### Before Releases
- Full organization pass
- Ensure nothing in wrong place
- Update README if structure changed

## Anti-Patterns

### ❌ Documentation Sprawl
```
root/
├── NOTES.md
├── IDEAS.md
├── RANDOM_THOUGHTS.md
├── TEMP.md
└── ...15 more random files
```

### ❌ Source Directory Docs
```
src/
├── backend/
│   ├── BACKEND_NOTES.md     # Wrong! Move to docs/
│   └── API_DESIGN.md        # Wrong! Move to docs/
```

### ❌ No Clear History
```
root/
├── OLD_PLAN.md              # When? What milestone?
├── OLD_OLD_PLAN.md          # Confusing!
└── FINAL_PLAN_REAL.md       # Which is current?
```
